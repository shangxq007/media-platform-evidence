# Bounded interaction architecture (before implementation)

Authority and scope: root AGENTS.md applies; no nested AGENTS.md exists under frontend. Latest Owner task explicitly permits unfrozen frontend iteration and forbids commits/freezes, so it overrides root candidate-freeze verification and integration/retirement procedure. No integration is performed. Any durable instruction alignment is a separate Owner governance task. Existing dirty files, external ledger, stash and historical layout evidence are preserved. Only frontend paths are writable for this task.

Selection ownership: one shell SelectionContext owns active surface, workspace/project route scope, selectedObjects array and primarySelectedObject, plus optional simulated playhead/range. References are frontend presentation identities, never canonical authorization. A keyed provider lifetime resets synchronously on surface/workspace/project changes; surface adapters register/unregister within that lifetime. No effect copies shared selection back and forth. Adapter handlers update existing presentation models; shared objects are refreshed by explicit actions. Focus does not select. Selection and inspector visibility are independent.

Action lowering: a discriminated ProductAction/InteractionIntent union defines LOCAL_EPHEMERAL selection/inspect/Agent actions, WORKSPACE_PRESENTATION rename/move/reveal, READ_ONLY_QUERY explicit revision comparison and CANONICAL_SEMANTIC unavailable requests. All local selection entry points and proposal applications dispatch through the same context dispatcher. Typed surface adapters lower presentation actions to current Canvas and NLE handlers and read-only requests to Review's existing guarded compare handler. Command descriptors are discovery only. Existing canonical timeline preview/confirm/apply remains in its existing typed application gateway with all gates intact; generic semantic requests reject centrally before adapters.

Shell: horizontal Studio only. Remove B URL state, propagation, choice buttons and B CSS/test branches. One shell-owned contextual right inspector renders selection properties, collapses without selection loss and becomes an explicit mobile sheet. Canvas viewport controls collapse behind More controls; selection action bar has at most three primary actions plus More and Ask Agent. Agent launcher is compact in the shell toolbar; conversation expands into a modal desktop drawer/mobile sheet. Shared accessible dialog primitive supplies focus entry/trap/restore, Escape and backdrop dismissal for Agent, mobile inspector and command shell.

Synthetic boundary: explicit opt-in clip fixture uses a stable presentation-only CLIP ID in a synthetic lane, simulation steps 0–20, no DTO/head identity or decoded media. Agent accepts a labeled user intent and deterministically recognizes inspect/reveal/rename and revision questions; unknown intent remains unsupported. Proposals capture a monotonic selection-context revision and scope, rejecting selection changes even if selection later returns. Canonical Apply stays disabled with creator-first explanation and secondary diagnostics. Local presentation Apply is separate. Review proposals identify the chosen revision pair but invent no diff facts; comparison uses the existing typed gateway path or states analysis is not integrated. All three required synthetic evidence flags and projection label remain visible in expanded Agent.

TDD: first fail new pure selection/action/proposal tests; implement reducer/dispatcher; add component boundary tests for shared Canvas/clip selection, all invocation sources, current palette, stale proposals, context reset, accessible dialog behavior and read-only Review pair. Preserve existing canonical operation and revision comparison proofs. Retire only B-specific test variants; adapt existing inspector assertions to the single shell inspector while retaining semantics.

Validation: frontend Vitest machine-readable reports, lint, typecheck, architecture guard and its tests, then production build with --outDir dist. Cache/temp under frontend/node_modules/.cache. Guard allowlists/ledger are not edited; ledger-only failures will be manifested. No browser commands or sockets. Hermes will run copied fixture/BiDi harness and the new scenario. Path census distinguishes current sources/tests/build, prior evidence, new evidence and caches; proposed final ledger alignment only, no ledger mutation.

Implementation finding: remounting all provider children on project changes would discard NLE's existing in-flight apply ownership and break the proven deferred-HEAD-load boundary. SelectionProvider therefore replaces its store synchronously when the scope key changes without remounting children. Canvas/Review keep their existing project session keys. This preserves application request lifetimes while resetting shared presentation selection/proposals before commit. The existing apply ownership test remains unchanged and is the regression gate.
